# 오늘 살 수 있는 집

서울 아파트 매수를 위한 개인 자산 시뮬레이터 MVP입니다. 현금, 본인·배우자 소득, 기존 부채, 생애최초 여부를 입력하면 **현재 설정한 정책·대출 조건에서 가능한 최대 매수가**를 역산합니다. 보존할 현금과 거래비용을 먼저 고려하고 LTV·DSR·스트레스 금리·대출 총액 제한을 함께 적용합니다.

> **현재 정책·금융상품·금리는 모두 mock 데이터입니다.** ‘오늘 기준’이나 ‘현재 정책 반영’은 실시간 금융기관 공시 확인을 뜻하지 않습니다. DB를 연결해도 외부 데이터 수집기는 mock 구현을 사용합니다.

이 문서는 [package.json](package.json), [package-lock.json](package-lock.json)과 현재 `src/`, `prisma/`, `scripts/`, `tests/`의 구현을 기준으로 작성했습니다.

## 빠른 실행

**권장 환경: Node.js 22.22.0, npm.** DB 없이도 데모를 실행할 수 있습니다. 저장소 URL은 실제 주소로 바꾸세요. 이미 내려받았다면 프로젝트 루트에서 의존성 설치부터 진행합니다.

```sh
git clone YOUR_REPOSITORY_URL home-today
cd home-today
npm ci
npm run db:generate
npm run dev
```

[http://localhost:3000](http://localhost:3000)에 접속합니다. 데모에서는 `.env`가 필요 없으며 `DATABASE_URL`을 설정하지 않아야 합니다. Prisma 클라이언트는 서버 코드에서 import하므로 데모에서도 생성합니다.

Windows에서는 [scripts/run.mjs](scripts/run.mjs)가 `node_modules/node/bin/node.exe`가 있으면 이를 우선 사용합니다. 다른 환경에서는 실행 중인 Node를 사용합니다. **설치 명령과 lint·typecheck는 이 래퍼를 거치지 않으므로 시스템 Node도 권장 버전으로 맞추는 편이 좋습니다.**

구형 Windows Node로 설치해 네이티브 테스트 의존성이 누락됐다면 프로젝트 Node로 재설치할 수 있습니다. npm CLI 경로는 설치 위치에 맞게 변경하세요.

```powershell
& .\node_modules\node\bin\node.exe 'C:\Program Files\nodejs\node_modules\npm\bin\npm-cli.js' install --include=optional
```

프로덕션 실행은 `npm run build` 후 `npm run start`입니다. 현재 build 스크립트는 `next build --webpack`을 실행합니다.

시나리오 카드를 선택하면 상품 비교·금리 차트·비용 상세가 해당 가격을 기준으로 바뀝니다. 상단 최대 매수가 카드는 항상 최대 시나리오를 표시합니다. ‘시나리오 비교’ 화면에서는 상품 표를 숨깁니다. 상품명을 누르면 우대조건·첫해 이자·총이자 상세를 펼칩니다.

**초기값은 예시입니다.** 현금 4억 5천만원, 본인 소득 8,500만원, 배우자 소득 4,500만원, 보존 현금 5천만원, 기존 부채 0원이며 혼인·생애최초는 켜져 있습니다. 초기 대출 조건은 연 5.0%, 30년, 5년 고정 후 변동, 원리금균등입니다. mock 상품 금리는 연 4.7~5.5% 범위입니다.

### 저장 범위

- 입력은 Zustand 메모리에 유지되며 자산 계산을 위해 서버로 전송하지 않습니다.
- **설정 저장**은 자산 객체 하나를 `localStorage`의 `home-today-assets`에 덮어씁니다. 금리·상환 조건, 상품 선택, 선택한 시나리오는 저장하지 않습니다.
- 우측 상단 **나** 버튼으로 저장한 자산을 불러옵니다. 새로고침 시 자동 복원하지 않으며, 불러올 때 Zod로 검증합니다.
- 가구 순자산은 별도 입력값으로, 현금·부채 변경에 맞춰 자동 갱신되지 않습니다.
- 사용자 계정과 자산 DB 저장 API는 없습니다. `AssetProfile`은 스키마만 있습니다.

저장한 자산을 지우려면 브라우저 개발자 도구에서 `localStorage.removeItem('home-today-assets')`를 실행합니다.

## 최대 매수가 계산

주요 구현: [자산 계산](src/domain/assets/index.ts), [대출 한도](src/domain/mortgage/products.ts), [가격 역산](src/domain/purchase/index.ts).

```text
총 보유 현금 − 반드시 남겨둘 현금 → 매수에 사용할 현금 C
후보 집값 P → 거래비용 F(P)와 대출 한도 L(P) 계산
P + F(P) ≤ C + L(P)를 만족하는 최대 가격 탐색
→ 자기자본·필요 대출·남는 현금·상환액 계산
```

### 현금과 대출 한도

| 항목                  | 현재 계산                                                                    |
| --------------------- | ---------------------------------------------------------------------------- |
| 사용 가능 현금 `C`    | `max(0, cash − reserves 합계)`                                               |
| 적용 소득 `I`         | `income + (married ? spouseIncome : 0)`                                      |
| 기존 부채 상환액 `D`  | 모든 부채의 `annualPayment` 합계. 잔액에서 자동 추정하지 않음                |
| DSR 월 상환 여력      | `max(0, I × policy.dsr − D) / 12`                                            |
| 심사 금리             | `실제 금리 + stressRate × stressFactors[금리 유형]`                          |
| LTV 한도              | `floor(P × 적용 LTV)`; 일반 또는 생애최초 구분                               |
| 일반 대출 한도 `L(P)` | LTV 한도, DSR로 역산한 원금, 가격 구간별 규제 한도, 선택 상품 한도 중 최솟값 |

DSR 상환 여력을 심사 금리·만기로 원금으로 환산합니다. 원리금균등은 월납입 공식의 역함수, 원금균등은 `floor(월 여력 / (1/개월수 + 심사금리/12))`를 사용합니다. 만기는 정책의 `maxYears` 이내입니다.

**기존 부채 잔액은 현금에서 차감하거나 DSR로 자동 환산하지 않습니다.** 연간 상환액이 0이면 DSR에 반영되지 않으며, 잔액이 있는 경우 화면에 주의를 표시합니다. 혼인 시 소득 합산은 공동차주 가정이며 실제 단독차주 심사를 구현한 것은 아닙니다.

정책대출을 선택하면 `eligibility`에서 소득·가격·순자산·추가 자격 플래그를 검사하고, 디딤돌은 85㎡ 초과도 제외합니다. 소득 한도는 일반 DSR 대신 **DTI 여력과 실제 금리의 원리금균등 역함수**로 계산합니다. 기존 부채의 연간 원리금 전액을 차감하는 근사이며, 원금균등을 선택해도 이 정책대출 한도 환산식은 동일합니다.

### 가격 역산과 시나리오

`maxPurchasePrice`는 `C + 정책상 가장 큰 총액 한도`를 탐색 상한으로 잡고, 세금·중개보수·정책 가격 경계와 경계 다음 1원을 기준으로 구간을 나눠 이분 탐색합니다. 후보 가격마다 비용과 한도를 다시 계산하며, 선택한 상품이 있다면 자격도 검사합니다. 사용 가능한 현금이 없거나 적합한 후보가 없으면 0원을 반환합니다.

최대 가격에서 0 / 3천만원 / 5천만원 / 1억원을 차감해 4개 시나리오를 만들고 음수 가격은 0원으로 처리합니다. 각 시나리오에서:

```text
필요 대출 = max(0, 매수가 + 거래비용 − C)
적용 대출 = min(필요 대출, 대출 한도)
필요 자기자본 = 매수가 − 적용 대출
거래 후 현금 = 총 현금 − 필요 자기자본 − 거래비용
```

가능한 시나리오에서는 보존 현금을 유지하면서 낮춘 가격만큼 대출을 우선 줄입니다. 무대출이 되면 남는 현금이 늘어납니다. 상단 ‘실제 투입 자기자본’은 `max(0, C − 거래비용)`이며, 시나리오의 필요 자기자본과는 계산 정의가 다릅니다.

**최대 가격은 모든 금융상품 중 최적 상품을 탐색한 결과가 아닙니다.** 초기에는 기본 조건, 상품 선택 후에는 해당 상품 기준입니다. 금리·상환 조건을 직접 바꾸면 상품 선택을 해제하고 사용자 설정으로 계산합니다.

## 상환·금리 시뮬레이션

구현: [mortgage/index.ts](src/domain/mortgage/index.ts), [comparison.ts](src/domain/mortgage/comparison.ts).

원금 `B`, 월 이율 `r = 연이율/12`, 개월수 `n`일 때:

- **원리금균등:** `ceil(B × r × (1+r)^n / ((1+r)^n − 1))`. 0%는 `ceil(B/n)`.
- **원금균등:** 매월 `ceil(최초 원금/n)` 원금과 잔액에 대한 이자를 납부. 마지막 원금은 남은 잔액으로 제한.
- **월 상환액:** `amortize().monthly`는 첫 회차 원리금입니다. 원금균등의 월평균이 아닙니다.
- **첫해·총이자:** 잔액 기준 월 이자를 원 단위 반올림해 각각 첫 12개월, 전체 상환기간에 걸쳐 합산합니다. 연도별 원금·이자·잔액도 반환하지만 별도 상환표 UI는 없습니다.

| 금리 유형 | 현재 / −1%p / +1%p / +2%p 처리                                                                                                    |
| --------- | --------------------------------------------------------------------------------------------------------------------------------- |
| 고정형    | 모든 시나리오에서 최초 금리를 만기까지 유지                                                                                       |
| 변동형    | 첫 회차부터 변경 금리를 적용하고 이후 유지                                                                                        |
| 혼합형    | 고정기간에는 최초 금리 유지. 이후 변경 금리를 적용하고 원리금균등 납입액은 남은 원금·기간으로 재산정. 원금균등의 회차 원금은 유지 |

변경 금리는 최소 0%입니다. 금리 차트는 변동·고정형의 첫 회차, 혼합형의 **고정기간 종료 직후 회차**를 표시합니다. 기본 시나리오·상품 표의 총이자는 현재 금리가 계속 유지되는 가정이며, 차트의 ±%p 비교는 대출 원금을 고정한 상환 민감도 분석입니다.

Decimal.js는 원리금 공식·역함수·월 이자·일부 세금에 사용합니다. 현금 합산, 일부 비용·한도 계산에는 JavaScript `number`와 반올림·버림도 사용하므로 전 계산이 Decimal인 것은 아닙니다. 입력은 정수 원이며, 화면은 1만원 이상 금액의 만원 미만을 생략합니다. **총이자는 ‘첫 월납입액 × 개월수’가 아니라 실제 회차별 이자 합계**입니다.

## 정책 데이터와 변경 이력

정책 타입은 [types.ts](src/domain/types.ts), 기본 버전은 [policy/mock.ts](src/domain/policy/mock.ts)에 있습니다.

| 필드                                      | 역할                                                     |
| ----------------------------------------- | -------------------------------------------------------- |
| `version`, `effectiveDate`, `checkedAt`   | 버전 식별자, 모의 시행일, 확인 시각                      |
| `source`, `mock`                          | 참고 자료 제목·URL, mock 여부                            |
| `ltv`, `firstHomeLtv`, `dsr`              | 일반·생애최초 LTV와 DSR                                  |
| `stressRate`, `stressFactors`, `maxYears` | 스트레스 가산금리·유형별 반영률·최장 만기                |
| `mortgageLimits`                          | 가격 상한 `upTo`별 대출 총액 `limit`                     |
| `tax`                                     | 취득세 가격 경계, 감면 한도, 교육세·농특세·비용 계수     |
| `policyMortgage`                          | 보금자리론·디딤돌별 소득·가격·순자산·대출 한도와 LTV·DTI |

현재 버전은 `MOCK-2026.09-v2`, 이전 버전은 `MOCK-2026.08-v1`입니다. 현재 일반/생애최초 LTV는 40%/70%, DSR은 40%, 만기는 최대 30년입니다. 스트레스 가산금리는 이전 1.5%p → 현재 3%p이며, 고정형은 0%, 변동·혼합형은 100% 반영합니다. 모의 총액 한도는 15억원 이하 6억원, 25억원 이하 4억원, 그 초과부터 fixture 상한인 1조원까지 2억원입니다.

정책과 계산을 분리하면 같은 엔진에 이전·현재 정책을 넣어 영향을 비교할 수 있습니다. 다만 **취득세율 공식, 중개보수 구간, 인지세 구간은 아직 `tax/index.ts` 내부 상수**입니다. 정책 snapshot만 바꿔 모든 세법을 변경할 수 있는 구조는 아닙니다.

### ‘현재 정책 반영’의 실제 동작

1. 클라이언트가 본문 없이 `POST /api/policy`를 호출합니다.
2. `MockPolicyProvider`가 현재 fixture를 반환하면서 `checkedAt`만 현재 시각으로 갱신합니다. 인터넷 조회는 하지 않습니다.
3. 저장소의 첫 번째 정책과 `diffPolicies`로 규칙 필드를 비교합니다. 버전명·시행일·출처·확인 시각 자체는 변경 비교 대상이 아닙니다.
4. `{ policy, previous, changes, storage }`를 반환합니다. 변경 항목은 `{ field, before, after, description }` 형태로 계산하며 별도 변경 내역 테이블에 저장하지 않습니다.
5. 변경이 있으면 사용자 자산과 현재 상환 조건으로 전후 매수가를 계산합니다. 실패하면 API는 503, 화면은 오류 알림과 기존 계산을 유지합니다.

기본 fixture에서는 새로고침을 반복해도 ‘모의 정책 변동 없음’입니다. 정책 히스토리는 현재·직전 버전의 영향과 전체 버전 목록을 보여주며, 임의의 두 버전을 선택하는 UI는 없습니다. **정책 영향 함수에는 선택 상품을 넘기지 않으므로 상품별 한도·정책대출 자격을 반영한 비교는 아닙니다.**

### 저장소

| 실행 모드           | 동작                                                                                      |
| ------------------- | ----------------------------------------------------------------------------------------- |
| `DATABASE_URL` 없음 | fixture 2개를 반환. `save()`는 아무 작업도 하지 않으며 새로고침 이력은 영구 저장되지 않음 |
| `DATABASE_URL` 있음 | Prisma로 `effectiveDate` 내림차순 조회. 정책 upsert와 확인 기록 생성을 트랜잭션으로 실행  |

`PolicyVersion`은 버전·시행일·확인일·출처·JSON 규칙·mock 여부를 저장하고 `version`은 unique입니다. 같은 버전은 DB 열의 `checkedAt`만 갱신하며 `rules` snapshot은 덮어쓰지 않습니다. `PolicyCheck`는 확인 시각·버전·변경 여부를 기록합니다. 조회는 `rules` JSON을 그대로 반환하므로 재조회한 snapshot의 `checkedAt`과 DB 열의 최신 확인 시각은 다를 수 있습니다.

최초 페이지에서 DB 조회가 실패하면 안내와 mock 화면을 제공하고, DB가 비어 있어도 fixture로 표시합니다. 실제 DB 연결·마이그레이션·seed는 별도로 준비해야 합니다.

## Mock과 외부 데이터의 구분

| 데이터                           | 현재 출처                                                                       |
| -------------------------------- | ------------------------------------------------------------------------------- |
| 정책과 이전 이력                 | `policy/mock.ts`의 2개 버전 또는 이를 seed한 DB snapshot. 실제 정책 수집기 없음 |
| 금융사·상품·금리·우대조건·기준일 | `mortgage/products.ts`의 `mockProducts` 7개. 실제 은행 API 호출 없음            |
| 시작 자산                        | `assets/index.ts`의 `defaultAssets`; 이후 사용자 입력 또는 브라우저 저장값      |
| 출처 링크                        | 정책 fixture에 기재한 참고 URL. 링크의 본문을 앱에서 수집·검증하지 않음         |

일반 은행 상품은 별도 신용 자격 검증 없이 비교 대상입니다. 정책 상품만 모의 소득·가격·순자산·면적·추가 자격을 검사합니다. `policyQualified`는 사용자 가정 플래그이며 자격 증빙을 검증하지 않습니다.

상품 정렬은 **필요 한도 충족 +100점, 정책상품 +20점, 혼합형 +5점**, 동점이면 낮은 금리 순입니다. 우대조건 충족을 계산해 실제 금리를 산출하는 방식이 아닙니다. 한도 부족 상품의 월납입액도 필요 대출금 기준 참고값이며, 선택하면 해당 상품에서 가능한 최대 가격으로 다시 계산합니다.

교체 지점인 [providers.ts](src/server/providers.ts)에 `PolicyProvider.fetchLatest()`와 `MortgageRateProvider.listProducts()` 인터페이스가 있지만 **현재 실제 외부 금융·정책 데이터 연동은 없습니다.**

## PostgreSQL 실행과 환경변수

Docker Compose를 사용할 경우 프로젝트 루트에서 다음을 실행합니다. 아래 `.env` 복사는 PowerShell 기준이며, 기존 파일이 있으면 덮어쓰지 말고 값을 확인하세요.

```powershell
docker compose up -d
Copy-Item .env.example .env
npm run db:generate
node scripts/run.mjs prisma migrate deploy
npm run db:seed
npm run dev
```

`migrate deploy`는 저장소의 기존 SQL 마이그레이션을 적용하는 실제 CLI 명령입니다. 스키마를 수정해 개발 마이그레이션을 만들 때는 등록된 `npm run db:migrate`를 사용합니다. seed는 mock 버전 2개를 upsert하며 기존 버전은 변경하지 않습니다.

| 환경변수       | 사용처·설정                                                                                                |
| -------------- | ---------------------------------------------------------------------------------------------------------- |
| `DATABASE_URL` | `schema.prisma`, `server/policy-repository.ts`. DB 모드에만 필요. 예시는 [.env.example](.env.example) 참고 |
| `CI`           | `playwright.config.ts`. 값이 있으면 기존 테스트 서버를 재사용하지 않음. 일반 로컬 실행에서는 설정 불필요   |
| `PATH`         | `scripts/run.mjs`가 기존 시스템 값 앞에 선택한 Node 경로를 추가. 별도 `.env` 설정 불필요                   |

앱의 별도 `POLICY_API_URL`, 금융 API 키, `NEXT_PUBLIC_*` 환경변수는 없습니다. Compose의 `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`는 컨테이너 초기화용이며 값은 로컬 개발 예시입니다. 실제 접속 정보는 커밋하지 않습니다.

## 설계 원칙과 현재 한계

- **UI와 계산 분리:** 테스트 가능한 domain 함수가 결과를 반환하고 컴포넌트는 입력·선택·표시에 집중합니다.
- **정책 주입과 provider 분리:** 이전·현재 정책을 같은 함수로 비교하며 외부 연동 교체 지점이 있습니다. 일부 세금 구간은 아직 함수 내부에 있습니다.
- **타입·금액 처리:** TypeScript strict, 자산 복원 시 Zod 검증, 정수 원 반환과 Decimal 중간 계산을 사용합니다. 외부 정책 응답·DB JSON의 런타임 스키마 검증은 아직 없습니다.
- **컴포넌트·반응형:** 자산·시나리오·상품·금리·정책 컴포넌트를 나누고 360px 브라우저 테스트를 둡니다.

다주택 중과, 담보평가·방공제, 전세보증금 승계, 개인 신용점수, 은행 총량 제한, 실거주·전입·토지거래허가 요건, 정책대출의 신혼·자녀·연령별 특례 등은 자동 판단하지 않습니다. 정책대출 한도 산식과 일부 UI의 DSR 표시는 실제 상품별 심사 구분을 완전히 표현하지 않습니다.

결과는 자산 계획을 위한 참고용이며 **실제 대출 승인·금리·세금을 보장하지 않습니다.** 신용도, 금융사 심사, 우대조건, 기존 부채, 적용 정책에 따라 실제 금액은 달라집니다.
